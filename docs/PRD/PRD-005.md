# PRD-005: 보안 사건 관리

## 1. 배경

- 현재 문제: 알림·통화·앱 설치에서 발생한 위험을 통합 기록하지 않으면 가족이 사건의 진행 상태를 확인할 수 없다.
- 왜 지금 필요한가: 자녀 웹 대시보드와 통화 간 연관성 판단을 위한 공통 데이터 저장소가 필요하다.
- 관련 문서/이슈: 「부모 지킴이 상세 기획서」 4·6·12장

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 자녀가 본인 가족의 위험 사건과 요약·지시·대응 상태를 조회한다.
- 비즈니스 또는 운영상 기대 효과: 단발성 경고가 아닌 연속 사건의 흐름을 확인할 수 있다.

## 3. 대상 사용자

- 주요 사용자: 자녀
- 보조 사용자: 부모님, 자녀 웹, AI 분석·위험 대응 서비스
- 관리자 또는 운영자 영향: 사건 발생·분석 실패를 추적할 수 있다.

## 4. 범위

이번 작업에 포함:

- [ ] 알림·통화·앱 설치 사건 공통 저장
- [ ] AI 위험 분류·요약·지시 및 분석 상태 관리
- [ ] 가족별 사건 목록·상세 조회
- [ ] 사건 대응 상태 갱신 및 중복 이벤트 방지

이번 작업에 포함하지 않음:

- [ ] 통화 원본을 자녀에게 공개
- [ ] 고급 통계·주간 리포트·관리자 분석 화면

## 5. 사용자 흐름

1. Android 또는 AI 분석 결과로 보안 사건이 생성·갱신된다.
2. 자녀가 웹에서 가족의 사건 목록을 확인한다.
3. 자녀가 사건 상세 요약·위험 지시를 조회하고 대응 상태를 갱신한다.

## 6. 기능 요구사항

- FR-1: `SecurityEvent`에 가족·유형·위험 수준·상태·발생 시각을 기록한다.
- FR-2: 통화에서 추출한 `CallInstruction`을 사건과 연결해 저장한다.
- FR-3: `GET /api/v1/events`, `GET /api/v1/events/{id}`로 가족별 기록을 제공한다.
- FR-4: 사건 확인/완료 상태를 갱신하고 중복 이벤트를 방지한다.

## 7. 비기능 요구사항

- 성능: 최근 사건부터 목록 조회하고 결과 수를 제한한다.
- 접근성: 웹이 이해하기 쉬운 요약·상태·시간 정보를 제공한다.
- 보안: 가족별 조회 권한, 원본 미노출, 최소 정보 보관.
- 로깅/모니터링: 사건 생성·상태 변경·처리 실패를 추적한다.

## 8. 수용 기준

- [ ] Given 분석 완료된 위험 메시지, When 사건 목록을 조회하면, Then 발생 시각·유형·요약이 표시된다.
- [ ] Given 통화 위험 지시, When 사건 상세를 조회하면, Then 관련 지시 유형이 포함된다.
- [ ] Given 다른 가족 사용자, When 사건 상세를 요청하면, Then 접근이 거부된다.

## 9. 검증 계획

- 단위 테스트: 사건 상태 변경·중복 판별.
- 통합 테스트: 분석 결과 저장 → 웹 사건 목록 조회.
- 수동 확인: 가족별 사건 격리와 원문 비노출 확인.

## 10. 리스크와 열린 질문

- 리스크: 중복 수신·분석 재시도로 사건이 중복 생성될 수 있다.
- 열린 질문: 사건 보존 기간, 대응 완료 상태 정의, 사건 간 연관성 표현 방식.
