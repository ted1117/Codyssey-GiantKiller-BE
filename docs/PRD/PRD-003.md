# PRD-003: 가족 확인·위험 대응

## 1. 배경

- 현재 문제: 사칭 의심 메시지를 AI가 판단하더라도 가족의 직접 확인이나 후속 행동과 연결되지 않는다.
- 왜 지금 필요한가: 자녀 확인과 통화 지시·앱 설치 간 연결이 서비스의 핵심 차별점이다.
- 관련 문서/이슈: 「부모 지킴이 상세 기획서」 4·5·7장 기능 ②·④

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 자녀가 사칭 의심 메시지 발송 여부를 답하고, 부모님은 결과를 안내받는다.
- 비즈니스 또는 운영상 기대 효과: AI 판단에 가족 검증을 추가하고 위험 행동을 조기에 발견한다.

## 3. 대상 사용자

- 주요 사용자: 자녀, 부모님
- 보조 사용자: Android 앱, AI 분석 결과
- 관리자 또는 운영자 영향: 확인 요청 만료와 매칭 실패를 확인한다.

## 4. 범위

이번 작업에 포함:

- [ ] 사칭 의심 사건에 자녀 확인 요청 생성
- [ ] `SENT`·`NOT_SENT` 응답과 만료 상태 처리
- [ ] 중복·권한 없는 응답 차단
- [ ] 앱 설치 완료 이벤트와 최근 통화 지시 비교

이번 작업에 포함하지 않음:

- [ ] Android의 실제 앱 설치 강제 차단
- [ ] 금융 이체 차단 및 실시간 통화 감청

## 5. 사용자 흐름

1. AI가 자녀 사칭 위험을 감지하면 서버가 확인 요청을 생성한다.
2. 자녀가 발송 여부를 응답하면 서버가 상태를 갱신하고 알림 기능에 전달한다.
3. 별도로 앱 설치 완료 이벤트가 오면 최근 통화 지시와 비교해 위험 여부를 기록한다.

## 6. 기능 요구사항

- FR-1: 확인 요청을 `PENDING`으로 생성하고 만료 시각을 저장한다.
- FR-2: `POST /api/v1/verify/respond`의 응답자·가족·기한을 검증한다.
- FR-3: 최초 유효 응답 또는 만료에 따라 상태를 확정한다.
- FR-4: `POST /api/v1/actions/app-install` 수신 시 최근 `INSTALL_*` 지시와 앱 정보를 비교한다.

## 7. 비기능 요구사항

- 성능: 응답과 매칭은 짧은 DB 조회·갱신으로 처리한다.
- 접근성: 부모님 안내는 간결하고 확인 여부가 명확해야 한다.
- 보안: 자녀 응답 권한 검증, 중복 응답 방지, 안전성 과장 금지.
- 로깅/모니터링: 상태 전이·만료·매칭 결과를 기록한다.

## 8. 수용 기준

- [ ] Given 확인 대기 요청, When 등록된 자녀가 `NOT_SENT`로 응답하면, Then `DENIED`로 확정되고 경고 요청이 생성된다.
- [ ] Given 만료된 확인 요청, When 응답하면, Then 기존 결과를 덮어쓰지 않는다.
- [ ] Given 설치 지시가 저장된 통화, When 관련 앱 설치 완료 이벤트가 오면, Then 위험 연관성이 기록된다.

## 9. 검증 계획

- 단위 테스트: 확인 상태 전이·만료·앱 매칭 규칙.
- 통합 테스트: AI 분류 → 확인 → 알림, 통화 지시 → 앱 설치 이벤트 → 알림.
- 수동 확인: 자녀 `보냈어/안 보냈어` 버튼과 무응답 시나리오.

## 10. 리스크와 열린 질문

- 리스크: FCM 지연, 자녀 오응답, 정상 원격지원 앱의 오탐.
- 열린 질문: 확인 만료 시간, 하나의 요청에 참여하는 자녀 수, 앱 매칭 기준.
