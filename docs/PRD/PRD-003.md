# PRD-003: 자녀 사칭 확인·대응

## 1. 배경

- 현재 문제: 사칭 의심 메시지를 AI가 판단하더라도 가족의 직접 확인이나 후속 행동과 연결되지 않는다.
- 왜 지금 필요한가: 자녀의 직접 확인을 통해 사칭 의심 메시지에 대응한다.
- 관련 문서/이슈: 「부모 지킴이 상세 기획서」 4·5·7장 자녀 사칭 확인 기능

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 자녀가 사칭 의심 메시지 발송 여부를 답하고, 부모님은 결과를 안내받는다.
- 비즈니스 또는 운영상 기대 효과: AI 판단에 가족 검증을 추가하고 위험 행동을 조기에 발견한다.

## 3. 대상 사용자

- 주요 사용자: 자녀, 부모님
- 보조 사용자: Android 앱, AI 분석 결과
- 관리자 또는 운영자 영향: 확인 요청 상태·만료·처리 실패를 확인한다.

## 4. 범위

이번 작업에 포함:

- [x] 사칭 의심 사건에 자녀 확인 요청 생성
- [x] `SENT`·`NOT_SENT` 응답과 만료 상태 처리
- [x] 중복·권한 없는 응답 차단

자녀 사칭 확인 서버 범위를 구현·검증했다. 실제 AI 입력·FCM 발송·Android 화면 연결은 연동 후속 작업이다.
사용자 지시에 따라 이번 PRD의 기능 범위를 자녀 사칭 확인·대응으로 한정한다.

이번 작업에 포함하지 않음:

- [ ] 앱 설치 완료 이벤트 수신과 최근 통화 지시 비교 (PRD-006으로 이관)
- [ ] Android의 실제 앱 설치 강제 차단
- [ ] 금융 이체 차단 및 실시간 통화 감청
- [ ] 해커톤 범위에서 자녀 탈퇴·계정 비활성화에 따른 확인 대상 재선정과 진행 중 요청 보정

## 5. 사용자 흐름

1. AI가 자녀 사칭 위험을 감지하면 서버가 가족의 모든 자녀에게 확인 요청을 생성한다. 응답 기한은 서버의 요청 생성 시각부터 10분이다.
2. 자녀별 응답을 기록한다. 한 명이라도 `SENT`이면 발송 확인, 전원이 `NOT_SENT`이면 전원 발송 부인으로 확정한다. 그 외에는 대기하다가 기한이 지나면 확인 불가로 종료하고 결과를 알림 기능에 전달한다.

## 6. 기능 요구사항

- FR-1: 모든 자녀를 대상으로 확인 요청을 `PENDING`으로 생성하고, 생성 시각으로부터 10분 후를 만료 시각으로 저장한다.
- FR-2: `POST /api/v1/verify/respond`의 응답자·가족·기한을 검증하고 자녀별 응답을 한 번만 기록한다.
- FR-3: 기한 내 한 명이라도 `SENT`이면 발송 확인, 대상 자녀 전원이 `NOT_SENT`이면 `DENIED`로 확정한다. 일부 자녀의 `NOT_SENT`만 있으면 대기하며, 미확정 요청은 만료 시 확인 불가로 종료한다. 확정 결과를 뒤늦은 응답으로 덮어쓰지 않는다.
- FR-4: 대기 중에도 부모에게 송금·앱 설치·인증번호 전달을 보류하도록 즉시 안내한다. 발송 확인은 안전 보증이 아니며, 전원 발송 부인과 만료도 각각 사칭 확정과 안전 판정으로 표현하지 않는다.
- FR-5: 대상 자녀가 0명이면 생성 즉시 `EXPIRED`로 종료하고 확인 불가로 안내한다. 대상이 없는 경우를 전원 발송 부인으로 판정하지 않는다.

## 7. 비기능 요구사항

- 성능: 응답과 상태 확인은 짧은 DB 조회·갱신으로 처리한다.
- 접근성: 부모님 안내는 간결하고 확인 여부가 명확해야 한다.
- 보안: 자녀 응답 권한 검증, 중복 응답 방지, 안전성 과장 금지.
- 로깅/모니터링: 상태 전이·만료·처리 실패를 기록한다.

## 8. 수용 기준

- [x] Given 확인 대기 요청, When 기한 내 대상 자녀 전원이 `NOT_SENT`로 응답하면, Then `DENIED`로 확정되고 부모에게 전원 발송 부인 경고 요청이 생성된다.
- [x] Given 확인 대기 요청, When 기한 내 한 명이라도 `SENT`로 응답하면, Then 발송 확인으로 확정하되 메시지·링크의 안전을 보장하지 않는다.
- [x] Given 일부 자녀만 `NOT_SENT`로 응답한 요청, When 생성 후 10분이 지나면, Then 확인 불가로 종료하며 사칭이나 안전으로 단정하지 않는다.
- [x] Given 확인 요청 생성, When 자녀 응답을 기다리면, Then 부모에게 위험 행동 보류 안내가 즉시 요청된다.
- [x] Given 대상 자녀가 0명인 가족, When 확인 요청을 생성하면, Then 즉시 `EXPIRED`로 종료하고 확인 불가로 안내한다.
- [x] Given 만료된 확인 요청, When 응답하면, Then 기존 결과를 덮어쓰지 않는다.

## 9. 검증 계획

- 단위 테스트: 자녀별 응답 집계·확인 상태 전이·10분 만료.
- 통합 테스트: 저장된 사칭 의심 사건 → 확인 → 알림 요청 저장. 실제 AI·FCM은 해당 기능 연동 후 검증한다.
- 수동 확인: 자녀 `보냈어/안 보냈어` 버튼과 무응답 시나리오.

## 10. 리스크와 열린 질문

- 리스크: FCM 지연, 자녀 오응답, 실제 발신 자녀의 기기 고장·무응답.
- 확정 정책: 가족의 모든 자녀에게 요청, 한 명의 발송 확인 또는 전원의 발송 부인으로 확정, 생성 후 10분 만료 시 확인 불가.
- 확정 정책: 대상 자녀가 0명이면 즉시 `EXPIRED`로 종료하고 확인 불가로 안내한다.
- 연동 후속: PRD-002의 실제 AI 입력, PRD-004의 FCM 발송, Android 수신·응답 화면.
