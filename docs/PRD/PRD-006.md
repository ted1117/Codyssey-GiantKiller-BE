# PRD-006: 위험 행동(앱 설치) 감지

## 1. 배경

- 현재 문제: 통화 분석으로 의심 통화를 저장해도, 부모님이 그 뒤 원격제어 앱 같은 위험한 앱을 설치하는 순간을 가족이 알 수 없다.
- 왜 지금 필요한가: 해커톤 시연의 핵심 장면인 '통화 뒤 위험한 순간 멈춤'의 서버 기능이 없다.
- 관련 문서/이슈: 「부모 지킴이 상세 기획서」 4.2 기능 ④, 6.2 흐름 D, 7.1 ④. PRD-003 4절에서 보류한 '앱 설치 완료 이벤트 수신과 최근 통화 지시 비교'를 이 문서로 이관한다.
- 목적: 해커톤 시연 영상에서 기능이 동작하는 모습을 보여주는 최소 구현이다. 실제 서비스 운영 수준의 정확도·운영 정책은 다루지 않는다.

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 부모님 기기가 위험한 앱 설치를 알리면 부모님 앱이 경고를 띄우고 자녀가 긴급 알림을 받는다. 최근 의심 통화가 있었으면 '통화 뒤 설치'임을 함께 알린다.
- 비즈니스 또는 운영상 기대 효과: 피해 직전 행동을 가족이 즉시 알고 개입할 수 있다.

## 3. 대상 사용자

- 주요 사용자: 부모님, 자녀
- 보조 사용자: Android 앱(앱 설치 감지·경고창), 자녀 웹
- 관리자 또는 운영자 영향: 판정 결과와 알림 발송 실패를 로그로 확인한다.

## 4. 범위

이번 작업에 포함:

- [x] 부모님 기기의 앱 설치 이벤트 수신 API
- [x] 설치 정보만으로 위험 앱 설치를 판정
- [x] 위험 앱 설치 시 같은 가족의 최근 의심 통화 여부 확인과 결과 표시
- [x] 위험 앱 설치만 `APP_INSTALL` 사건으로 저장하고 자녀 조회에 공개
- [x] 위험 앱 설치 시 가족 자녀에게 긴급 FCM 알림 발송
- [x] 부모님 앱이 경고창을 띄울 수 있도록 판정 결과를 API 응답으로 반환

이번 작업에 포함하지 않음:

- [ ] Android의 앱 설치 감지·경고창 구현과 실제 설치 강제 차단
- [ ] 긴급 SMS 발송 (SMS 서비스 없음, PRD-004 후순위)
- [ ] 통화 지시 유형·키워드와 설치 앱의 대조
- [ ] 위험하지 않은 앱 설치의 저장·공개
- [ ] 같은 설치 이벤트의 중복 수신 방지
- [ ] 앱 설치 사건과 관련 통화 사건의 DB 연결
- [ ] 송금·이체 등 앱 설치 이외 행동의 감지

## 5. 사용자 흐름

1. 부모님 Android 앱이 새 앱 설치를 감지하고 대상 가족 하나와 설치 정보를 서버로 전송한다.
2. 서버가 기존 JWT와 해당 가족의 `PARENT` 역할을 검사한다.
3. 서버가 설치 정보만으로 6.1절의 규칙에 따라 위험 앱인지 판정한다.
4. 위험 앱이 아니면 아무것도 저장하지 않고 `matched=false`를 반환한다.
5. 위험 앱이면 같은 가족의 최근 의심 통화 여부를 확인하고, `APP_INSTALL` 사건을 저장·확정한 뒤 가족의 모든 자녀에게 긴급 알림을 발송한다. `matched=true`, 사건 ID, 최근 의심 통화 여부(`related_call`)를 반환한다.
6. 부모님 앱은 응답의 `matched=true`로 경고창을 띄우고, `related_call=true`이면 '통화에서 시킨 것' 문구를 쓸 수 있다. 자녀는 알림과 자녀 웹에서 사건을 확인한다.

## 6. 기능 요구사항

- FR-1: `POST /api/v1/actions/app-install`로 `family_id`, `package_name`, `app_label`, `is_unknown_source`, `occurred_at`(타임존 필수)을 받는다. 기존 JWT로 요청자를 식별하고 해당 가족의 `PARENT`만 허용한다.
- FR-2: 6.1절 규칙으로 위험 앱 설치를 판정한다. 통화 기록은 판정에 쓰지 않는다.
- FR-3: 위험 앱 설치이면 같은 가족에 6.2절의 최근 의심 통화가 있는지 확인한다.
- FR-4: 위험 앱 설치만 `SecurityEvent`(`event_type=APP_INSTALL`, `classification=RISKY_APP_INSTALL`, `requires_attention=true`, `analysis_status=COMPLETED`, 대응 상태 `OPEN`)로 저장한다. 요약은 서버가 만든 고정 문구에 앱 이름을 넣고, 최근 의심 통화 여부에 따라 문구를 달리한다.
- FR-5: 사건 저장을 확정한 뒤 가족의 모든 `CHILD`에게 새 알림 유형 `INSTALL_WARNING`을 발송한다. 부모님에게는 푸시를 보내지 않는다. 발송 실패는 사건과 응답을 바꾸지 않는다.
- FR-6: 응답은 `matched`, `event_id`(위험 앱이 아니면 `null`), `related_call`(위험 앱이 아니면 `false`)을 반환한다.
- FR-7: 자녀 조회 공개 조건에 `event_type=APP_INSTALL`이고 `requires_attention=true`인 사건을 추가한다. 응답 필드·권한은 PRD-005 6.0.2와 같다.

### 6.1. 위험 앱 설치 판정

다음 중 하나라도 맞으면 위험 앱 설치다.

- 원격제어 앱: 패키지명이 `com.teamviewer.`, `com.anydesk.`, `com.rsupport.`로 시작한다.
- 출처 불명 앱: `is_unknown_source=true`.

### 6.2. 최근 의심 통화

같은 가족의 `event_type=CALL`, `analysis_status=COMPLETED`, `requires_attention=true`인 사건 중 설치 시각 이전 24시간 안에 발생한 통화가 하나라도 있으면 `related_call=true`다. 통화 지시 내용은 보지 않는다.

## 7. 비기능 요구사항

- 성능: 위험 앱이 아니면 DB를 조회하지 않는다. 위험 앱이면 최근 의심 통화 존재 여부만 조회한다.
- 접근성: 부모님 앱이 즉시 경고창을 띄울 수 있도록 같은 요청에서 판정 결과를 반환한다.
- 보안: 위험하지 않은 설치 정보는 저장·로그하지 않는다. 패키지명은 사건에 저장하지 않는다. 통화 원문·지시 설명은 응답·푸시·로그에 포함하지 않는다.
- 로깅/모니터링: 위험 앱 설치의 사건 ID·최근 의심 통화 여부와 발송 실패만 기록한다.

## 8. 수용 기준

- [x] Given 최근 의심 통화가 있는 가족, When 원격제어 앱 설치가 수신되면, Then `APP_INSTALL` 사건이 저장되고 `matched=true`, 사건 ID, `related_call=true`를 반환한다.
- [x] Given 의심 통화가 없는 가족, When 출처 불명 앱 설치가 수신되면, Then 사건이 저장되고 `matched=true`, `related_call=false`를 반환한다.
- [x] Given 원격제어 앱이 아니고 출처가 확인된 앱 설치, When 수신되면, Then 사건·알림 없이 `matched=false`를 반환한다.
- [x] Given 정상·실패·분석 중 통화나 다른 가족의 의심 통화만 있는 경우, When 위험 앱 설치가 수신되면, Then `related_call=false`다.
- [x] Given 위험 앱 설치, When 사건이 확정되면, Then 가족의 모든 자녀에게 `INSTALL_WARNING` 발송을 시도하고 부모에게는 보내지 않는다. 발송 실패는 사건과 응답을 유지한다.
- [x] Given 부모가 아닌 요청자 또는 다른 가족 구성원, When 설치를 전송하면, Then 판정·저장 전에 거부한다.
- [x] Given 위험 앱 설치 사건, When 자녀가 사건 목록·상세를 조회하면, Then 사건이 공개된다.

## 9. 검증 계획

- 통합 테스트: 위 수용 기준을 API 호출로 확인한다. 의심 통화는 테스트 DB에 직접 저장한다.
- 수동 확인: AI 연결 후 통화 분석 → 원격제어 앱 설치 이벤트 전송 순서로 시연 흐름을 확인한다. AI 연결 전에도 의심 통화 없이 `related_call=false` 경고는 curl로 확인할 수 있다.

## 10. 리스크와 열린 질문

- 리스크: 자녀가 원격 지원용으로 설치한 원격제어 앱도 경고한다. 같은 설치를 다시 전송하면 사건과 알림이 중복된다. 설치 시각을 클라이언트가 보내므로 시각이 틀리면 `related_call`이 달라진다.
- 리스크: 원격제어 앱 목록이 3개 접두어로 고정되어 다른 원격제어 앱은 출처 불명 조건으로만 잡힌다.
- 열린 질문: 부모님 경고창 문구를 서버에서 내려줄지 여부.
