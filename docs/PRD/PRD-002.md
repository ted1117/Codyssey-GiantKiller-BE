# PRD-002: 위험 이벤트 수집·AI 분석

## 1. 배경

- 현재 문제: Android가 수집한 알림과 통화 녹음을 서버에서 일관되게 분석할 흐름이 없다.
- 왜 지금 필요한가: 위험 판단 결과가 가족 확인·사건 기록·알림 기능의 입력이 된다.
- 관련 문서/이슈: 「부모 지킴이 상세 기획서」 4·5·7장

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 부모님 기기가 알림 또는 녹음을 전송하면 위험 분류·요약·행동 지시 분석 결과를 얻는다.
- 이번 완료 목표: 해커톤 영상에서 준비된 문자와 짧은 녹음으로 분석·사건 저장·기존 서비스 연결 흐름을 시연한다.
- 운영 고도화보다 시연에 필요한 최소 연결을 우선한다. 실제 AI API에 맞출 필수 입력·출력 계약은 생략하지 않는다.

## 3. 대상 사용자

- 주요 사용자: 부모님
- 보조 사용자: Android 앱, 별도 AI 서버
- 관리자 또는 운영자 영향: 시연 요청의 결과와 통화 사건의 분석 실패를 확인한다.

## 4. 범위

이번 작업에 포함:

- [x] 마스킹된 알림 수신 및 AI 메시지 분석 API 연결
- [x] 시연용 짧은 녹음 파일 업로드 및 STT·통화 분석 연결(백엔드 내 faster-whisper STT + LLM 게이트웨이)
- [ ] AI 호출 전 모든 정상 접수 통화의 사건 저장과 같은 사건의 분석 결과·실패 기록
- [ ] 시연에 필요한 AI 결과 검증과 기존 사건·자녀 알림 서비스 연결
- [ ] 자녀 사칭 문자 사건을 기존 가족 확인 서비스에 연결

이번 작업에 포함하지 않음:

- [ ] Android의 알림·녹음 자동 수집 구현
- [ ] Whisper 모델 개발·학습·LLM 프롬프트 개발(백엔드가 사전학습 `faster-whisper small`을 실행만 한다. 별도 AI 서버는 두지 않는다)
- [ ] RAG·벡터 데이터베이스
- [ ] 동일 발신자의 통화 이력 조회와 `caller_hash` 저장·연관 분석
- [ ] 별도 기기 등록·기기 인증 체계, 여러 가족으로 사건 자동 복제
- [ ] 긴 녹음의 비동기 작업·별도 worker·큐·작업 상태 조회 API
- [ ] 업로드 멱등성·자동 재시도·서버 재시작 후 분석 복구
- [ ] 사건 목록·상세·대응 변경 API와 일반적인 녹음 보관 기능
- [ ] 가족 확인 알림의 실제 기기 수신 검증. FCM 발송 시도는 2026-10-31 PRD-004 연결로 구현했다.

## 5. 사용자 흐름

### 5.1. 통화

1. 로그인한 부모의 앱이 대상 가족 하나와 동의된 시연용 녹음 파일을 전송한다.
2. 백엔드가 입력·가족 소속·부모 역할을 검증하고 AI 호출 전에 통화 사건을 `PENDING`으로 저장·확정한다.
3. 같은 사건을 `PROCESSING`으로 변경·확정하고, 요청 내에서 AI 서버의 분석 결과를 기다린다.
4. 정상 결과는 같은 사건에 `COMPLETED`와 `NOT_REQUIRED`로 저장하고 자녀에게 알리지 않는다. 위험·의심 결과는 `COMPLETED`와 `OPEN`으로 저장한 뒤 기존 자녀 알림 서비스를 호출한다.
5. AI 호출·시간 초과·응답 검증 실패는 같은 사건에 `FAILED`로 기록한다. 실패를 정상·안전으로 표시하지 않는다.
6. 사건 ID와 분석 결과 또는 실패 상태를 반환하고 임시 녹음 파일이 있으면 정리한다.

### 5.2. 문자

1. 로그인한 부모의 앱이 대상 가족 하나와 마스킹된 문자를 전송한다.
2. 백엔드가 입력·권한을 검증하고 AI 메시지 분석 결과를 요청 내에서 기다린다.
3. 검증된 결과가 `CHILD_IMPERSONATION`이면 사건을 저장하고 `VerificationService.create(event_id)`로 가족 확인 요청과 알림 요청을 저장한다.
4. 검증된 결과가 `CHILD_IMPERSONATION`이 아니고 `requires_attention=true`이면 `ALERT` 사건(`COMPLETED`·`OPEN`)을 저장한다. commit 후 해당 가족의 모든 자녀에게 `RISK_WARNING` 알림을 발송하고 부모에게는 보내지 않는다. 발송 실패는 사건과 응답을 바꾸지 않는다.
5. 분석 결과와 생성된 사건·확인 요청 ID를 반환한다. 위험 문자 사건에는 확인 요청이 없어 `verification_id`는 `null`이다. 가족 확인 알림 요청 저장을 실제 FCM 전달로 표시하지 않는다.

`requires_attention=false`인 자녀 사칭 이외 문자는 분석 결과 반환까지만 포함하며 사건·알림을 만들지 않는다(2026-10-31 사용자 승인으로 위험 문자 사건화를 추가).

## 6. 기능 요구사항

- FR-1: `POST /api/v1/alerts/check`로 마스킹된 메시지를 분석하고 결과를 반환한다. 자녀 사칭이면 기존 가족 확인 서비스까지 호출한다. 자녀 사칭이 아니어도 `requires_attention=true`이면 `ALERT` 사건을 저장하고 가족 자녀에게 `RISK_WARNING`을 발송하며, `false`이면 결과만 반환한다.
- FR-2: `POST /api/v1/calls/analyze`로 시연용 음성 파일을 접수하고 같은 요청에서 분석 결과 또는 실패 상태를 반환한다. 별도 작업 ID와 상태 조회 API는 만들지 않는다.
- FR-3: 기존 JWT로 요청자를 식별하고 요청의 `family_id` 하나에 대한 소속·`PARENT` 역할을 검사한다. 부모 사용자 ID를 클라이언트 입력으로 신뢰하지 않으며 여러 가족으로 자동 배포하지 않는다.
- FR-4: 기존 `EventService`의 통화 생성·분석 시작·완료·실패 기능을 재사용한다. 정상 통화와 분석 실패도 삭제하지 않고 같은 사건에 유지한다.
- FR-5: 실제 AI 응답을 검증해 내부 `CallAnalysisResult`로 변환한다. 시연에 필요한 분류·위험 수준·지시 유형과 정상/위험·의심 매핑만 맞추고 범용 분류 체계는 만들지 않는다.
- FR-6: 판정 필수값 누락·해석할 수 없는 분류·잘못된 응답을 안전 판정으로 대체하지 않는다. 문자 분석 실패도 오류로 반환한다.
- FR-7: AI 연결이 미설정이면 입력·권한 검증 후 사건 생성 전에 `503 AI_NOT_CONFIGURED`를 반환한다. 일반 요청에 가짜 분석 결과를 반환하지 않으며 테스트에서만 AI 응답을 주입한다.
- FR-8: `CHILD_IMPERSONATION`의 `requires_attention`은 `true`여야 한다. `false`가 함께 온 결과는 검증 실패로 처리하고 사건 완료·가족 확인·위험 알림으로 전달하지 않는다. 통화는 기존 사건에 분석 실패를 기록한다.

## 7. 비기능 요구사항

- 성능: 시연용 짧은 녹음만 대상으로 요청 내에서 결과를 기다린다. AI 호출에는 유한한 시간 제한을 두며 네트워크 대기 중 DB 트랜잭션·잠금을 유지하지 않는다.
- 접근성: 요청 응답에서 분석 결과와 실패를 구분한다. 분석 상태는 기존 사건에 기록하되 별도 진행률·상태 조회 기능은 제공하지 않는다.
- 보안: 기존 JWT와 가족별 부모 권한을 검사한다. 녹음은 준비된 시연 형식과 크기 상한을 검사하고 요청 처리 중에만 사용하며 임시 파일은 성공·실패 시 정리한다.
- 로깅/모니터링: 처리 시간·실패 원인만 기록하며 메시지·음성 원문은 로깅하지 않는다.

## 8. 수용 기준

- [ ] Given 자녀 사칭 문자, When 메시지 분석이 성공하면, Then 사칭 사건·가족 확인 요청·알림 요청이 저장되고 사건·확인 요청 ID가 반환된다.
- [ ] Given 권한 있는 부모의 유효한 테스트 녹음, When AI 분석을 호출하기 전, Then 통화 사건이 이미 저장되어 있다.
- [ ] Given 위험·의심 녹음, When 분석이 완료되면, Then 같은 사건에 결과·지시를 저장하고 해당 가족 자녀에게 기존 알림 서비스를 호출한다.
- [ ] Given 정상 녹음, When 분석이 완료되면, Then 사건은 `COMPLETED`·`NOT_REQUIRED`로 유지되고 자녀 알림은 호출하지 않는다.
- [ ] Given AI 호출·시간 초과·응답 검증 실패, When 통화 분석이 종료되면, Then 기존 사건에 `FAILED`를 남기고 안전 판정이나 자녀 위험 알림으로 대체하지 않는다.
- [ ] Given 타 가족 또는 부모 역할이 아닌 요청자, When 분석을 요청하면, Then AI 호출·사건 생성 전에 거부한다.
- [ ] Given 허용되지 않은 형식 또는 크기 상한 초과 녹음, When 업로드하면, Then AI 호출·사건 생성 전에 거부한다.
- [ ] Given 성공 또는 실패한 녹음 처리, When 요청 처리가 끝나면, Then 임시 녹음 파일이 남지 않는다.
- [ ] Given AI 연결 미설정, When 권한 있는 부모가 유효한 요청을 보내면, Then `503 AI_NOT_CONFIGURED`를 반환하고 사건·가족 확인·알림을 생성하지 않는다.
- [x] Given 자녀 사칭이 아니고 `requires_attention=true`인 문자 결과(예: `FRAUD`), When 분석이 완료되면, Then `ALERT` 사건을 `COMPLETED`·`OPEN`으로 저장하고 가족 확인 요청 없이 `event_id`만 반환하며, commit 후 가족의 자녀에게 `RISK_WARNING`을 발송한다. `requires_attention=false`면 사건·알림 없이 결과만 반환한다. 발송 실패는 사건과 200 응답을 유지한다.
- [ ] Given `CHILD_IMPERSONATION`과 `requires_attention=false`인 AI 결과, When 결과를 검증하면, Then 502로 거부하고 통화는 기존 사건에 `FAILED`를 기록한다. 문자 사건·가족 확인·위험 알림은 생성하지 않는다.

## 9. 검증 계획

- 자동 검증: 준비된 AI 응답을 사용해 입력·권한·결과 매핑, 통화 사건 선저장·정상/위험/실패 처리, 문자 가족 확인 연결과 임시 파일 정리를 검사한다.
- 실제 연동 확인: 준비된 문자와 짧은 녹음을 실제 AI 서버로 보내 결과·사건 저장을 확인한다. 가짜 AI 응답을 사용한 검증과 구분한다.
- 영상 시연: 자녀 사칭 문자, 위험 녹음, 정상 녹음의 최소 흐름을 확인한다. 실제 FCM·Android 수신은 별도로 검증하며 알림 서비스 호출만으로 수신 완료를 주장하지 않는다.

## 10. 리스크와 열린 질문

- 리스크: 요청이 AI 분석 완료까지 대기하므로 AI·클라이언트 시간 제한의 영향을 받는다. 시연용 짧은 파일로 실제 소요 시간을 확인한다.
- 최소 구현의 한계: 같은 녹음의 재전송은 사건·알림을 중복 생성할 수 있고, 서버 종료 시 분석 상태가 남을 수 있다. 이번에는 자동 복구하지 않는다.
- 임시 파일 정리는 정상 실행 중 성공·예외 처리 범위다. 강제 종료 후 파일·작업 복구는 후속이다.
- 연동 전 필요한 최소 확인: 실제 AI 요청·응답 예시, AI가 녹음을 받아 STT·분석하는 호출 방식, 정상/위험·의심 매핑, 시연 파일의 허용 형식·최대 크기와 AI 호출 시간 제한. 구체적인 필드·제한값은 `SPEC-002`에서 정한다.
- 통화 이력·비동기 작업·별도 기기 인증·자동 재시도는 이번 구현의 선결 조건으로 두지 않는다.
- 2026-10-31 실제 AI 연결: LLM은 `CHILD_IMPERSONATION`·`FRAUD`·`NORMAL` 3분류를 반환한다. 자녀 사칭 문자는 가족 확인 흐름(5.2의 3단계)으로 전달되고 통화는 해당 분류로 저장된다. 3분류의 정확도는 모델에 달려 있으며 실제 샘플로 확인한다. 통화 `instructions`는 비어 있다. STT는 별도 AI 서버가 아니라 백엔드 프로세스에서 실행한다. 크기 상한은 10 MiB(413)이며 형식 검사(415)는 적용하지 않는다. 설계는 SPEC-002 4.1·11절을 따른다.
