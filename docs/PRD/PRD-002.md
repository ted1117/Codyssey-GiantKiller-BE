# PRD-002: 위험 이벤트 수집·AI 분석

## 1. 배경

- 현재 문제: Android가 수집한 알림과 통화 녹음을 서버에서 일관되게 분석할 흐름이 없다.
- 왜 지금 필요한가: 위험 판단 결과가 가족 확인·사건 기록·알림 기능의 입력이 된다.
- 관련 문서/이슈: 「부모 지킴이 상세 기획서」 4·5·7장

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 부모님 기기가 알림 또는 녹음을 전송하면 위험 분류·요약·행동 지시 분석 결과를 얻는다.
- 비즈니스 또는 운영상 기대 효과: 복수 채널의 피싱 징후를 한 서비스에서 처리한다.

## 3. 대상 사용자

- 주요 사용자: 부모님
- 보조 사용자: Android 앱, 별도 AI 서버
- 관리자 또는 운영자 영향: 분석 요청의 성공·실패 상태를 확인한다.

## 4. 범위

이번 작업에 포함:

- [ ] 마스킹된 알림 수신 및 AI 메시지 분석 API 연결
- [ ] 녹음 파일 업로드 및 STT·통화 분석 API 연결
- [ ] 동일 발신자의 최근 통화 요약·지시를 AI 맥락으로 전달
- [ ] AI 결과 스키마 검증 및 보안 사건 관리 기능에 전달

이번 작업에 포함하지 않음:

- [ ] Android의 알림·녹음 자동 수집 구현
- [ ] Whisper 모델 실행·LLM 프롬프트 개발
- [ ] RAG·벡터 데이터베이스

## 5. 사용자 흐름

1. Android 앱이 개인정보를 마스킹한 알림 또는 동의된 녹음 파일을 업로드한다.
2. 백엔드가 입력을 검증하고 AI 서버에 분석을 요청한다.
3. 백엔드가 결과를 검증해 사건 관리에 전달하고 분석 상태를 반환한다.

## 6. 기능 요구사항

- FR-1: `POST /api/v1/alerts/check`로 메시지 분석을 요청한다.
- FR-2: `POST /api/v1/calls/analyze`로 음성 파일 분석 작업을 접수한다.
- FR-3: 동일 `caller_hash`의 최근 요약·지시를 조회해 후속 통화 분석에 활용한다.
- FR-4: 분류값과 지시 타입을 정의된 스키마로 검증하고 실패를 기록한다.

## 7. 비기능 요구사항

- 성능: 긴 통화 분석은 요청과 분리하여 작업 상태를 관리한다.
- 접근성: 클라이언트가 분석 진행·완료·실패 상태를 알 수 있다.
- 보안: 가족·기기 인증, 오디오 형식·크기 제한, 통화 원본 최소 보관.
- 로깅/모니터링: 처리 시간·실패 원인만 기록하며 메시지·음성 원문은 로깅하지 않는다.

## 8. 수용 기준

- [ ] Given 자녀 사칭 문자, When 알림 분석 API를 호출하면, Then `CHILD_IMPERSONATION` 결과가 처리된다.
- [ ] Given 테스트 녹음, When 분석을 요청하면, Then 위험 지시가 구조화되어 사건 관리에 전달된다.
- [ ] Given AI 응답 오류, When 스키마 검증에 실패하면, Then 안전 판정으로 오인하지 않고 실패 상태를 남긴다.

## 9. 검증 계획

- 단위 테스트: 입력 검증 및 AI 응답 스키마.
- 통합 테스트: FastAPI ↔ AI 서버 ↔ 사건 저장.
- 수동 확인: 실제 알림 및 테스트 녹음 파일 전송.

## 10. 리스크와 열린 질문

- 리스크: 녹음 파일 접근 제한, STT 오류, 분석 지연, 개인정보 노출.
- 열린 질문: AI API 계약, 파일 최대 크기, 작업 상태 조회 방식, 이전 통화 조회 시간 범위.
