# PRD-001: 사용자·가족 관리

## 1. 배경

- 현재 문제: 부모님과 자녀의 계정·소속 관계가 없어 위험 사건의 수신자와 접근 권한을 결정할 수 없다.
- 왜 지금 필요한가: 사건 분석과 알림 기능이 의존하는 사용자 식별 체계를 먼저 마련해야 한다.
- 관련 문서/이슈: 「부모 지킴이 상세 기획서」 6·7·9장

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 회원가입·로그인 후 가족에 가입하고 자신의 기기를 등록한다.
- 비즈니스 또는 운영상 기대 효과: 올바른 가족에게만 위험 정보를 공유하고 알림을 전달한다.

## 3. 대상 사용자

- 주요 사용자: 부모님, 자녀
- 보조 사용자: Android 앱, 자녀 웹
- 관리자 또는 운영자 영향: 별도 관리자 UI 없이 가입·기기 등록 오류를 로그로 확인한다.

## 4. 범위

이번 작업에 포함:

- [ ] FastAPI Users 기반 회원가입·로그인 및 인증
- [ ] 가족 생성·참여와 `PARENT`/`CHILD` 역할 구분
- [ ] 기기 및 FCM 토큰 등록·갱신
- [ ] 가족별 접근 권한 검증

이번 작업에 포함하지 않음:

- [ ] 소셜 로그인 및 구독 결제
- [ ] 관리자 대시보드

## 5. 사용자 흐름

1. 사용자가 회원가입하고 로그인한다.
2. 사용자가 가족을 생성하거나 초대를 통해 참여한다.
3. 사용자가 기기를 등록하고, 서버는 가족 역할을 확인하여 접근을 허용한다.

## 6. 기능 요구사항

- FR-1: 계정을 인증하고 현재 사용자를 식별한다.
- FR-2: 가족 및 구성원 관계를 저장한다.
- FR-3: 기기·FCM 토큰을 사용자에 연결한다.
- FR-4: 모든 가족 관련 API에서 소속과 역할을 검사한다.

## 7. 비기능 요구사항

- 성능: 소규모 시연 사용자 요청을 정상 처리한다.
- 접근성: Android·웹이 동일한 인증 API를 사용한다.
- 보안: 비밀번호 해싱, 인증 토큰 검증, 가족 간 정보 격리.
- 로깅/모니터링: 인증 실패·권한 거부를 기록하며 비밀번호·토큰 원문은 기록하지 않는다.

## 8. 수용 기준

- [ ] Given 미가입 사용자, When 회원가입·로그인하면, Then 인증된 API를 호출할 수 있다.
- [ ] Given 부모님과 자녀, When 같은 가족에 참여하면, Then 역할과 가족 관계가 저장된다.
- [ ] Given 타 가족 사용자, When 가족 정보에 접근하면, Then 거부된다.

## 9. 검증 계획

- 단위 테스트: 가족 소속·역할 권한 검사.
- 통합 테스트: 가입 → 가족 연결 → 기기 등록.
- 수동 확인: Android와 웹에서 각자 로그인·접근 확인.

## 10. 리스크와 열린 질문

- 리스크: 잘못된 가족 초대로 타인에게 위험 요약이 공유될 수 있다.
- 열린 질문: 가족 초대 코드의 발급·만료 정책과 한 계정의 다중 기기 허용 여부.
