# PRD-004: 알림 관리

## 1. 배경

- 현재 문제: 분석 결과와 가족 확인 결과가 있어도 사용자 기기에 전달할 공통 알림 체계가 없다.
- 왜 지금 필요한가: 가족이 위험 상황에 개입하려면 사건 유형에 맞는 신호를 전달해야 한다.
- 관련 문서/이슈: 「부모 지킴이 상세 기획서」 4·7·12장

## 2. 목표

- 사용자가 무엇을 할 수 있어야 하는가: 부모님은 위험 경고를, 자녀는 확인 요청·위험 요약을 받는다.
- 비즈니스 또는 운영상 기대 효과: 대응이 필요한 사건을 놓치지 않도록 가족 협력을 지원한다.

## 3. 대상 사용자

- 주요 사용자: 부모님, 자녀
- 보조 사용자: Android 앱, 백엔드 사건·대응 서비스
- 관리자 또는 운영자 영향: 알림 발송 실패를 확인한다.

## 4. 범위

이번 작업에 포함:

- [ ] Firebase Admin SDK 기반 FCM 발송
- [ ] 부모님 경고 및 자녀 확인 요청·위험 요약 신호
- [ ] 사건 ID를 포함하는 일관된 데이터 페이로드
- [ ] 유효하지 않은 FCM 토큰·발송 실패 처리

이번 작업에 포함하지 않음:

- [ ] Android 알림 UI·오버레이 구현
- [ ] 긴급 SMS 발송(후순위)
- [ ] FCM 전달 또는 즉시 표시 보장

## 5. 사용자 흐름

1. 사건 분석 또는 가족 확인 처리로 알림 요청이 발생한다.
2. 백엔드가 대상 가족·역할·기기를 확인하고 FCM을 발송한다.
3. Android 앱이 수신한 신호에 따라 알림 또는 경고 화면을 표시한다.

## 6. 기능 요구사항

- FR-1: 기기별 FCM 토큰을 조회하고 대상 사용자에게 메시지를 보낸다.
- FR-2: 자녀 사칭 확인 요청에는 `event_id`와 응답 액션 정보를 포함한다.
- FR-3: 위험 경고·통화 요약·확인 결과에 맞는 메시지 유형을 제공한다.
- FR-4: 전송 실패를 기록하고 사건 데이터 자체는 보존한다.

## 7. 비기능 요구사항

- 성능: 발송 요청이 사건 API를 장시간 차단하지 않도록 한다.
- 접근성: 사용자 역할에 맞는 짧고 이해하기 쉬운 문구를 전달한다.
- 보안: FCM 페이로드에는 민감한 메시지·통화 원문을 포함하지 않는다.
- 로깅/모니터링: 발송 대상 ID·메시지 유형·성공·실패 기록.

## 8. 수용 기준

- [ ] Given 사칭 의심 사건, When 확인 요청이 생성되면, Then 해당 자녀 기기로 FCM 발송이 시도된다.
- [ ] Given 자녀의 발송 부인, When 확인 결과가 확정되면, Then 부모님 기기로 경고 신호가 전달된다.
- [ ] Given 유효하지 않은 토큰, When 발송이 실패하면, Then 오류가 기록되고 사건은 유지된다.

## 9. 검증 계획

- 단위 테스트: 메시지 유형별 페이로드 생성.
- 통합 테스트: Firebase 테스트 기기로 FCM 발송.
- 수동 확인: 부모님·자녀 기기에서 수신 및 버튼 동작 확인.

## 10. 리스크와 열린 질문

- 리스크: 절전 모드·네트워크 상태에 따른 전달 지연, 오버레이 제한.
- 열린 질문: 발송 재시도 정책, 토큰 갱신 주기, 앱 미수신 시 대체 안내 방식.
